# Merch Shop API

REST API сервис для управления внутренним магазином мерча. Позволяет сотрудникам покупать товары за внутреннюю валюту (монетки) и передавать монетки друг другу.

---

## Требования

Требования к сервису описаны [тут](https://github.com/avito-tech/tech-internship/blob/main/Tech%20Internships/Backend/Backend-trainee-assignment-winter-2025/Backend-trainee-assignment-winter-2025.md).

## Основные возможности

- **Покупка мерча**: 10 видов товаров с фиксированными ценами
- **Перевод монеток**: Безопасные переводы между сотрудниками
- **История операций**: Полная история полученных и отправленных монеток
- **Инвентарь**: Список купленных товаров для каждого пользователя

---

## Технологии

- **Язык**: Go 1.23
- **База данных**: PostgreSQL 15
- **API**: RESTful JSON API
- **Аутентификация**: JWT
- **Контейнеризация**: Docker + Docker Compose

## Установка и запуск

### Требования

- Docker 20.10+
- Docker Compose 2.0+

### Запуск

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/l-golofastov/Merch-Shop-Api.git
   cd Merch-Shop-Api
   ```

2. Создайте `.env` файл в корне проекта (пример в `env.example`):
   ```bash
   cp env.example .env
   ```
   Требуется указать следующие переменные окружения:
   * **SERVER_ADDRESS**: Адрес поднимаемого сервера внутри приложения (при запуске в докере необходимо указать ```0.0.0.0:8080```). Может быть полезна при спецификации адреса сервера при ручной сборке
   * **SERVER_TIMEOUT**: Таймаут времени запроса
   * **SERVER_IDLE_TIMEOUT**: Таймаут разрыва соединения с клиентом
   * **POSTGRES_HOST**: Адрес для подключения к БД. Может быть полезна для доступа с хоста
   * **POSTGRES_PORT**: Порт для подключения к БД. Может быть полезна для доступа с хоста
   * **POSTGRES_USERNAME**: Имя пользователя БД
   * **POSTGRES_PASSWORD**: Пароль пользователя БД
   * **POSTGRES_DBNAME**: Название БД
   * **TEST_POSTGRES_HOST**: Адрес для подключения к тестовой БД с хоста
   * **TEST_POSTGRES_PORT**: Порт для подключения к тестовой БД с хоста
   * **TEST_POSTGRES_USERNAME**: Имя пользователя тестовой БД
   * **TEST_POSTGRES_PASSWORD**: Пароль пользователя тестовой БД
   * **TEST_POSTGRES_DBNAME**: Пароль пользователя тестовой БД
   * **JWT_SECRET**: Секретный ключ для подписи JWT токенов

3. Запустите сервисы:
   ```bash
   make run
   ```

4. Приложение будет доступно на `http://localhost:8080`

## API

API соответствует [спецификации](https://github.com/avito-tech/tech-internship/blob/main/Tech%20Internships/Backend/Backend-trainee-assignment-winter-2025/schema.json).

### Основные эндпоинты

- `POST /api/auth` - Аутентификация (получение JWT)
- `GET /api/info` - Информация о балансе и истории операций
- `POST /api/sendCoin` - Перевод монеток другому пользователю
- `GET /api/buy/{item}` - Покупка товара

## Проблемы и решения

### Вопрос 1: Как задать конфиг приложению?

**Решение**: Производится парсинг ```.env``` файла, поскольку данный подход позволяет просто конфигурировать приложение централизованно в одном месте.

### Вопрос 2: Что делать при аутентификации уже существующего пользователя?

**Решение**: При каждой аутентификации генерируется новый токен, который действует 24 часа. Такое решение более эффективно с точки зрения безопасности, нежели обновление токена только по истечении его срока действия.
